Notes

- Each group ran as its own job under the exclusive benchmark queue, alone on the machine. Mac corpus: the files of the 0.2 run plus `h264-aac-tags.mp4`, `audio-aac-priming.m4a`, `h264-two-audio-tags.mkv` and the two files over 4 GiB, regenerated with `tools/corpus/generate.sh` (ffmpeg 8.0 there, so the bytes differ from the x64 corpus' files of the same name). `flac-cover-tags.flac` is not in the Mac corpus, so `tagw-flac` has two files.
- Tag-write rows edit the same four common fields of a file held in memory; the ratio is against TagLib#, the fastest managed comparator on every file. ATL.NET is 1.6x to 14x slower than TagLib# (its ratio column), least on WAV and most on `ilst`.
- **`tagw-mkv` misses the bar on this machine: 1.09x on its one file** (TagLib# is the only comparator that can edit it; ATL.NET fails on both Matroska files and TagLib# on `test1.mkv`). Reported as it is; on x64 the same row is 0.99x. A row with one file and a managed comparator that handles almost no Matroska is thin evidence in either direction.
- Rows `mkv-mux`, `remux-mem` and `playable` have no managed comparator, so they pass; times next to ffmpeg 8.0 and mkvmerge 103.0 are information.
- `remux-mem`: the bench's own peak figure is blank on macOS (the runtime reports no peak working set there), so the peaks were taken separately with `/usr/bin/time -l` around one child process per cell (one cold run plus the big-file samples each): 4.08 GiB MP4 to Matroska 73.3 MiB, to MP4 70.5 MiB; 4.14 GiB Matroska to Matroska 96.4 MiB, to MP4 90.6 MiB (ffmpeg `-c copy` 99.7 MiB and 40.7 MiB). Times on this Mac (10 to 27 s) are bound by the disk write, not by the remuxer.
- `playable`: 13.4 ms here, against 31.1 ms for ffmpeg 8.0 (information).
