# OneMedia

**Containers, metadata, subtitles; no decoding.** A managed .NET library for media containers, with no dependency beyond the .NET base class library. It reads and writes containers, edits metadata, repairs damaged files and rebuilds cut-off recordings, and covers subtitles and captions, capture facts, telemetry, timed events and a privacy strip. OneMedia is unaffiliated with other products or companies named OneMedia.

The goal is the depth of libavformat, GPAC, mkvtoolnix, MediaInfo and ExifTool in one library you can call from C#: demux and mux, lossless tag editing, evidence-backed capture time and place, subtitles and captions, repair, and HLS/DASH packaging. It never decodes or encodes an audio or video sample; audio decoding is handed to [OneAudio](https://github.com/recursive-ai-oss/oneaudio-csharp) through the `RecursiveAI.OneMedia.Audio` adapter.

## Status

**Version `1.0.2`: reading every container below (MP4/MOV/3GP, Matroska/WebM, MPEG-TS/PS and elementary streams, ASF, AVI, DV, Ogg, FLAC, FLV, MP3/ADTS/AC-3/AMR, WAV/AIFF/CAF), writing MP4/MOV/3GP/fragmented MP4/CMAF, Matroska/WebM, MPEG-TS/M2TS and WAV/BWF/RF64, remux (including to transport streams and WAV), faststart, trim, split and concat without re-encoding, tag editing, browser playability (`CanPlay`, `MakePlayable`, now with AAC and FLAC audio targets), a privacy strip for location and device identifiers, capture-date writes, and **repair** (rebuilding the indexes of damaged Matroska/WebM, AVI, MP4/MOV, fragmented MP4 and MPEG-TS files, and reconstructing truncated MP4/MOV/3GP recordings, always into a new file with a report), and **HLS/DASH packaging** (CMAF and transport-stream segments with HLS playlists and a DASH MPD, video on demand or live).** Also in this release, each with the limits stated below: packaging, HLS/DASH presentations and growing files as sources, capture facts as evidence, telemetry, timed events, and subtitles and captions (sidecars, container text tracks, CEA-608/708, SCC, teletext, bitmap subtitles). **Packaging has not passed a validator:** Apple `mediastreamvalidator` was not run (it needs an Apple ID sign-in) and the DASH-IF conformance tool v3.1.0 ran once (two findings, fixed) and then fails in its own base-URI handling; packaging is verified by packet equality with ffprobe and by playback in hls.js and dash.js in Chromium, Firefox and WebKit plus native HLS in macOS WebKit ([docs/packaging.md](docs/packaging.md)). **Sources have limits:** live DASH is not reloaded, HLS subtitle renditions are not read, a segment is held whole in memory up to `MediaLimits.MaxSegmentBytes`, and keyed segments are reported `Protected` and not decrypted ([docs/streaming-sources.md](docs/streaming-sources.md)). The tables below list what works and how it was checked; gaps are listed, not hidden.

```csharp
using RecursiveAI.OneMedia;
using RecursiveAI.OneMedia.Audio;   // package RecursiveAI.OneMedia.Audio

using var media = Media.Open("clip.mov");
Console.WriteLine($"{media.Duration} {media.Video?.Codec} {media.Audio?.Codec}");
Console.WriteLine($"{media.Tags.Title} {media.CaptureTime}");     // a fact prints its best value, or "none"
if (media.Location.TryGetValue(out var place))                      // absent facts have no value: no 0,0 stand-in
    Console.WriteLine($"{place.Latitude}, {place.Longitude}");
foreach (var candidate in media.CaptureTime.Candidates) Console.WriteLine(candidate);

using var pcm = media.Audio!.Decode();   // the audio track, decoded by OneAudio
```

`onemedia info <file>` (or `--json`) prints tracks, codecs (RFC 6381 strings), tags and facts with their candidate sources.

### Repair and reconstruction

`Media.Repair(input, output[, reference])` and `onemedia repair <in> <out> [--reference <file>]` write a **new file** and return a `RepairReport` (status, every structure rebuilt, fixed, dropped or guessed with its input byte range and a confidence, per-track packets kept and dropped, warnings). The input is never modified, payload bytes are copied unchanged, and a healthy file is reported `NothingToRepair`.

| Case | What it does | Limits |
|---|---|---|
| Damaged index of Matroska/WebM, AVI/OpenDML, MP4/MOV, fragmented MP4, MPEG-TS ([docs/repair.md](docs/repair.md)) | Rebuilds SeekHead, Cues, durations and cluster sizes (Matroska); `idx1`, OpenDML indexes and counts (AVI); `stco`/`co64`, durations and a cut-off `mdat` (MP4); `mfra`, `mehd` and a single `sidx` (fMP4); drops damaged PES packets and renumbers continuity counters (TS) | Checked on damaged variants made from healthy files (Matroska 17, AVI 16, MP4 13, fragmented MP4 14, TS 12 per source file) against ffprobe 7.0.2, with packets compared. **A TS file cut at 90 % keeps one cut frame** (observed in two sweep cases; see the limits in [docs/repair.md](docs/repair.md)). **M2TS (192-byte packets) has no oracle sweep**: ffmpeg 7.0.2 crashes on those files. ASF, FLV and Ogg are not repaired |
| Truncated MP4/MOV/3GP, movie box missing or cut ([docs/reconstruction.md](docs/reconstruction.md)) | Walks the media data and cuts it into samples with the codecs' own framing (H.264, HEVC, AV1, AAC, AMR, MP3, AC-3, PCM, GoPro metadata); writes the playable prefix, with each track's confidence and the input ranges its samples came from | **PCM audio, and video without in-stream parameter sets, need a reference file from the same device.** **5.1 AAC is dropped** (the frame probe does not take more than two channels). **Without a reference the AAC sample rate is a guess (44.1 kHz first) and the track is reported at Low confidence**; audio times may then be off. **AAC through the happy path needs the `.Audio` entry `AacReconstructionProbe.Repair` or the CLI**; `Media.Repair` in the core package has no AAC probe. Irregular frame durations of the original cannot be told from the stream. Fragmented files and an `mdat` split into several boxes are walked only up to the first `mdat` |

**Checked on generated files, published samples, 10 GoPro clips and 12 device models from the device corpus** ([docs/device-corpus.md](docs/device-corpus.md): iPhone, Pixel, Xiaomi and another Android phone, a Sony camcorder, Nikon, Olympus and Canon compact cameras; each cut at 60 % and rebuilt with no reference, a recording of the same model and the file itself). With a reference, every recovered sample's bytes and key flags equal the original's except one PCM packet at a cut (Pixel AAC with another recording as reference recovers 348 of 348 packets since 1.0.1); without a reference only files with parameter sets in the stream recover, and the others are refused with a request for a reference. Cut-off copies were made at 11 cut points of healthy files (some with the `mdat` size field or the `moov` zeroed), reconstructed with and without a reference, and compared with the original's packets (bytes, key flags, times) and ffmpeg 7.0.2 and MP4Box 26.07; the method is in [docs/reconstruction.md](docs/reconstruction.md). Real device recordings may have layouts the framing rules do not cover.

### Packaging and streaming sources

`Media.PackageHls`, `Media.PackageDash`, `Packager` and `onemedia package` cut a file (or, live, a forward-only stream) into CMAF segments (HLS also as transport-stream segments) with HLS media and multivariant playlists and a DASH MPD, as video on demand or live with a sliding window, one file per segment or one per track with byte ranges, a bit-rate ladder from several inputs, WebVTT subtitle renditions and timed events. The playlists and manifests are public models (`HlsPlaylist`, `DashMpd`) that read and write. `PresentationSource` and `Media.Open` read a local HLS playlist or DASH manifest as one media file, and `GrowingFileSource` reads fragmented MP4, live Matroska, MPEG-TS and FLV while they are written ([docs/packaging.md](docs/packaging.md), [docs/streaming-sources.md](docs/streaming-sources.md)).

**Limits, and what checked it:**
- **No validator has passed the output.** Apple `mediastreamvalidator` was not run (it needs an Apple ID sign-in). The DASH-IF conformance tool v3.1.0 ran once (two findings, both fixed) and then fails in its own base-URI handling on every run.
- **What did check it:** packet equality with the input through ffprobe (28 CMAF and 19 transport-stream inputs, 0 unexplained), TSDuck continuity on 38 of 38 transport-stream segment sets, and playback in hls.js 1.7.4 and dash.js 5.2.1 in Chrome 155, Firefox 141 and Playwright WebKit 26 (one failure: HEVC in transport-stream segments through hls.js in Chrome, not investigated) plus native HLS in macOS WebKit (7 of 7).
- **Packaging:** encryption is not written; live mode takes one input and holds the current segment in memory (a 2-hour soak plateaued at 106 MiB; a 10-minute real-time run stayed under 73 MiB).
- **Sources:** live DASH is not reloaded; HLS subtitle renditions are not read; a segment is held whole in memory, up to `MediaLimits.MaxSegmentBytes` (256 MiB); segments under `EXT-X-KEY` or `ContentProtection` are reported `Protected` and not decrypted; a progressive MP4 with `mdat` first cannot be read until it is finished. Packet-equal to ffprobe 8.1.3 on 34 generated presentations except for documented ffprobe behaviours.

### Subtitles and captions

One cue model (`SubtitleDocument`, exact `MediaTime`, styling spans, placement, word timing, bitmap images) with conversions that return a loss report, `Subtitles.Read`/`Write`/`Convert`, `MediaFile.Subtitles` (one list across container tracks, teletext pages, CEA-608 channels and CEA-708 services), and `onemedia subs`. Reading the container tracks costs no media reads; finding teletext and captions reads the video once on first access ([docs/subtitles.md](docs/subtitles.md)). **Speed:** subtitle parse and convert at 20,000 and 100,000 cues, against SubtitlesParser and Subtitle Edit's library, come out, in the 0.8 run, at a geometric mean of 0.53× for parsing and 0.40× for conversion on x64 (0.51× and 0.42× on arm64) of the fastest comparator, worst row 1.16× (x64, SRT at 100,000 cues) and 1.07× (arm64); SRT and large ASS parsing are close to Subtitle Edit's time, not ahead ([x64](docs/bench-results/0.8-x64.md), [arm64](docs/bench-results/0.8-arm64.md); the earlier 0.5 run is in [0.5-x64](docs/bench-results/0.5-x64.md) and [0.5-arm64](docs/bench-results/0.5-arm64.md)). **The CTA-608/708 and SCTE 35 standards were not available** (they need an account): caption parts rest on the ATSC A/53 and A/72 documents, the US regulation 47 CFR 79.101 and black-box ccextractor and ffmpeg output, and the open points are listed in [docs/captions.md](docs/captions.md).

**Timed events.** See the metadata table above: `tmcd`, SCTE 35 and timed ID3 are read, and `tmcd` tracks are carried by remux between MP4 and MOV; `emsg` boxes are reported as not written.

**Saving.** `Save()` writes a temporary file and renames it over the original: 500 `kill -9` rounds left no half-written target. Power loss has not been tested. It makes a new file: new inode, the saver's owner and group, and the original's extended attributes, ACLs and hard links are not kept. `SaveAs` writes a new file. `SaveInPlace` works only inside existing padding (`free`, `skip`, `Void`, ID3 or FLAC padding) and otherwise refuses with `PaddingRequired` and the file untouched; **it is not atomic** (300 kill rounds: 3 torn with the current two-pass writer, 7 with the first version).

**Removed tag values and leftovers.** On 0.3.0-preview.1, removing the last frames of an ID3v2 tag in place removed nothing: the frames stayed in the file as valid frames that readers still showed. 0.3.0-preview.2 fixed the removal, but saving an already affected file again did not remove the frames. From 0.3.0-preview.3, any save of an MP3 (`Save`, `SaveAs`, `SaveInPlace`, with edits or none) also zeroes leftover bytes and frames in the ID3v2 padding, a safeguard: we know of no sequence of calls in preview.1 or preview.2 that leaves removed values there. `onemedia tags <file> --check` (`TagWriter.CheckResidue`) reports such leftovers without printing them; it does not look at fields still in the tag. A field that preview.1 failed to remove is still an ordinary frame of the tag, which no version can tell from one you want to keep: open the file with this version, remove those fields again, save, and run `onemedia tags <file> --check --absent comment,composer`, which exits 1 and names each listed field still present in any tag system.

**Known limits.** Writing ASF is not implemented; the MP4 muxer writes one sample description per track, so joining files with different codec setups is refused; the Matroska muxer does not carry AAC priming, rotation, interlace or stereo mode; the Matroska trim drops tags, chapters and attachments; a common `Date` write keeps other date tags in the file and says so in `TagWriteReport.Warnings` (`Media.SetCaptureTime` writes every date field); editing ASF Metadata/Library objects, XMP outside ISO files, W64 and AVI is not implemented.

**Writer limits fixed in the 0.3 previews** ([docs/writer-review.md](docs/writer-review.md) section 6, [docs/writer.md](docs/writer.md)). Padding is generated as zero runs and an in-place save writes only the bytes that changed: a 3-byte ID3 title edit in a tag with 200 MiB of padding allocates 138 KB and writes 3 bytes (before: 419.5 MB and 209.7 MB), and `SaveAs` tag edits of files over 4 GB peak at 46 to 53 MiB. A growing edit leaves 1,024 bytes of padding so the next edit can be saved in place (`TagWriteOptions.Minimal` turns that off). Temporary files carry a recognisable name and stale ones are removed on the next save. `SaveInPlace` kill tests: 3 torn files in 300 rounds, which is why it stays documented as not atomic. What is tested for `Save` is `kill -9` (500 rounds, 0 corrupt targets); a power loss is not tested. The file is `fsync`ed before the rename, but the folder cannot be (the .NET base library cannot flush a directory), so after a power loss the rename may not be durable and the old name may still point at the old file.

**Real-device recordings** ([docs/device-corpus.md](docs/device-corpus.md)): 193 freely licensed recordings from phones, action cameras, drones, camcorders, compact cameras and screen recorders, compared with ffprobe, ExifTool and MediaInfo. Still open ([docs/device-corpus.md](docs/device-corpus.md)): the Olympus MOV1/MOV2 layouts (no sample) and the device classes not yet covered (Samsung phones, iPhone Dolby Vision, spatial and slow-motion video, Sony XAVC, dashcam originals, more GoPro and DJI telemetry). 1.0.1 fixed what the corpus showed in 1.0.0: strip now removes the serial number from DJI `djmd` samples of protocols outside the table of known layouts (the Osmo Pocket 3 recording carried a serial number and no position there), telemetry tracks no longer set the file duration, the AAC channel count follows the decoder configuration, a Pixel recording reconstructs with a sibling reference, leading pictures survive reconstruction of Nikon D5300 and Olympus TG-4 files, and Fujifilm AVI and Panasonic firmware fields are read. 1.0.2 fixed a privacy gap that 1.0.1 left: strip now removes the camera serial number from the `strd` chunk of a Fujifilm AVI (1.0.1 left it and its report did not say so), and the report names every vendor box, chunk, object, data track and trailer it has no rule for, so nothing is skipped silently ([docs/strip.md](docs/strip.md)).

**Gaps in this table, stated plainly.** Probe and metadata reads of transport streams stop their search for program tables at 6 MB: the four unusual streams that used to read up to 25 MB of a 30 MB file now read 6.3 to 7.1 MB (most: `foxksaz.ts`, 7,080,536 B in 26 requests of its 30.5 MB; ffprobe reads 6.0 to 14.3 MB on the same files), and the median transport stream is 476,352 B in 3 requests ([docs/io-results.txt](docs/io-results.txt), [docs/mpeg.md](docs/mpeg.md)). Probing an AVI makes 7 to 9 read calls on the file instead of 85 to 94 (the 0.8.0-preview.1 change notes said 48; that figure was wrong) and over HTTP the median AVI probe is now 114,509 B in 9 requests (before: 4,559 B in 32), about 172 KB in 9 requests for the 4.65 GB OpenDML file; fewer round trips cost more bytes. The arm64 numbers were taken on the Mac mini that has no multi-gigabyte corpus files and no MPEG transport streams, so its MPEG and over-4 GiB rows are absent.

Every parser is fuzzed (600 seconds per target when its code last changed; for this release the targets whose code changed since 0.6.0-preview.1, the manifest and presentation targets among them, were run again for 600 seconds, no open crash); damaged input is reported as typed defects with byte offsets and never surfaces as an untyped exception. Reading pulls packets with zero allocations per packet and constant memory at any file size.

## Building

```
dotnet build -c Release
dotnet test -c Release
dotnet pack -c Release
```

To run part of the suite, use the runner's own filters, for example `dotnet test --project tests/OneMedia.Tests -c Release --filter-class '*XiphFlvTests'` (also `--filter-method`, `--filter-namespace` with a full name, `--filter-query`). The VSTest-style `--filter` is not understood by this runner: `dotnet test` then reports "Handshake failures" and exit code 5 with zero tests.

Build output goes to `artifacts/` in the repository root (ignored by git). To build somewhere else, set `ONEMEDIA_SCRATCH` to a directory; output then goes to `$ONEMEDIA_SCRATCH/artifacts`. Test files are written under the system temporary directory (`TMPDIR`).

`smoke/OneMedia.AotSmoke` is published with NativeAOT and fails on any trim or AOT warning; `smoke/OneMedia.WasmSmoke` runs the same checks under the browser-wasm runtime (`wasm-tools` workload; run the built `AppBundle/main.mjs` with node), and `tests/OneMedia.Tests.Browser` runs the unit-test suite in headless Chromium (`tools/wasm-suite/run.sh`, `docs/platforms.md`). `tools/` holds the differential and I/O harness and the corpus scripts, `fuzz/` the fuzz targets and `bench/` the benchmarks; none of them ship.

## Contributing notes

- Clean room: the code is written from published specifications and from observing the behaviour of other tools as black boxes. The source of other media libraries and tools is not consulted.
- Every public type and member has an XML doc comment; warnings are errors.
- `unsafe` code, `Unsafe.*`, `MemoryMarshal` and intrinsics are not used.
